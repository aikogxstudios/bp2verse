## What You Already Do in Blueprints

This is the classic Unreal enemy pattern (and the exact example from the
`bp2verse` landing demo): you create a **`Blueprint Class`** with a **`Health`**
(`Integer`, default `100`) variable and a **`TakeDamage`** **`Custom Event`** or
**`Function`** taking an **`Amount`** (`Integer`) input. On execution, it
computes `Max(0, Health - Amount)` so health never goes negative, updates it
with **`Set Health`**, and runs a **`Branch`** (`Health <= 0` or
`Health == 0`) whose **`True`** pin triggers **`Print String`** with
`"Guard down"`.

- **Blueprint pattern:** `Blueprint Class` (`Health = 100`) →
  `Event TakeDamage` (`Amount`) → `Set Health` (`Max (Integer)` of `0` and
  `Health - Amount`) → `Branch` (`Equal (Integer)` `Health == 0`) → `True` →
  `Print String` (`"Guard down"`).
- **Official node names (EN):** `Blueprint Class`, `Custom Event` / `Function`,
  `Set` (`Health`), `Subtract` (`Integer - Integer`), `Max (Integer)`,
  `Equal (Integer)`, `Branch`, `Print String`.

The same logic, told twice: the node chain and its Verse shape.

## The Verse Equivalent

Here everything from Module 0 comes together in one working unit: a
**`class`**, a mutable `var Health` field, a `TakeDamage` method, the standard
`Max` function, an `if` acting as `Branch`, and archetype instantiation
`enemy{}`.

<Callout lang="en" variant="trap">
  Two habits break this snippet immediately: first, **`guard` is a reserved
  keyword** in Verse, so `guard := class:` fails to parse
  (`Syntax error: Unexpected ':='`; name the class `enemy`, while
  `"Guard down"` inside quotes is fine). Second, inside `if`, equality uses a
  **single `=`** (`if (Health = 0):`), never `==`
  (`Syntax error: Unexpected '='`).
</Callout>
